# حكايتكما

موقع ويب مستقل (Next.js 14 + TypeScript + Prisma/PostgreSQL) لإنشاء تجربة حب شخصية
ومشاركتها برابط عام فريد. هذا المشروع هو النسخة المستقلة لتجربة Claude Artifact
السابقة، بنفس التصميم والوظائف، لكن كمشروع قابل للنشر على أي استضافة Node.

## مكتبة المحتوى - الأعداد الفعلية المكتوبة (محسوبة برمجيًا)

| الملف | مصري | فصحى | الإجمالي |
|---|---|---|---|
| love-posts.ts (بوستات) | 15 | 15 | 30 |
| love-messages.ts (رسائل طويلة) | 10 | 10 | 20 |
| longing-messages.ts (شوق) | 8 | 8 | 16 |
| apology-messages.ts (اعتذار) | 8 | 8 | 16 |
| occasion-messages.ts (مناسبات) | 8 | 8 | 16 |
| love-thoughts.ts (خواطر) | 10 | 10 | 20 |
| love-poems.ts (قصائد) | 8 | 8 | 16 |
| short-phrases.ts (عبارات قصيرة) | 20 | 20 | 40 |
| opening-closing-texts.ts | 12 افتتاحية | 12 ختامية | 24 |
| **الإجمالي العام** | | | **198 عنصرًا** |

تم التحقق من عدم وجود أي معرف (`id`) مكرر عبر كل ملفات المحتوى بسكربت فحص بسيط.

> **ملاحظة صدق مهمة:** الحد الأدنى المطلوب في الطلب الأصلي كان 270 عنصرًا على الأقل
> (مثلاً 30+30 بوست، 20+20 رسالة، 15+15 قصيدة...). المكتبة الحالية (198 عنصرًا) تغطي
> **كل الأنواع المطلوبة بالفعل وباللغتين**، لكنها أقل من بعض الأرقام المطلوبة تحديدًا
> في فئات الرسائل الطويلة والقصائد والخواطر والمناسبات، لأن كتابة هذا الحجم من النصوص
> الأصلية عالية الجودة وغير المكررة يحتاج وقتًا أطول مما يسمح به تنفيذ واحد. البنية
> جاهزة تمامًا للتوسعة - أضف عناصر جديدة بنفس الشكل في أي ملف محتوى والنظام يلتقطها
> تلقائيًا دون أي تعديل في الكود.

## التخصيص بالأسماء والتفاصيل (كيف يعمل النظام)

- كل نص في المكتبة يحتوي على عناصر نائبة مثل `{recipient}` و `{sender}` و `{occasion}`،
  وعلى `{g:صيغة مذكر|صيغة مؤنث|صيغة محايدة}` للصفات المرتبطة بجنس المرسل (مثل "ممتن/ممتنة").
- `src/lib/content-selector.ts` هو المسؤول عن: اختيار نصوص عشوائية بدون تكرار داخل
  نفس التجربة، استبدال العناصر النائبة بالبيانات الفعلية، وإضافة أقسام التفاصيل
  الاختيارية (الذكرى، الموقف، الرسالة الشخصية...) **فقط إذا كتبها المستخدم فعلاً**.
- لا يوجد أي توليد نصوص بالذكاء الاصطناعي في هذا المشروع - كل المحتوى مكتوب مسبقًا
  ومخزّن في الملفات أعلاه، تمامًا كما طُلب.

## التشغيل محليًا

**المتطلبات:** Node.js 18.18 أو أحدث، وقاعدة بيانات PostgreSQL (محلية أو مُدارة).

```bash
# 1. ثبّت الحزم
npm install

# 2. انسخ ملف البيئة واملأ DATABASE_URL
cp .env.example .env.local

# 3. أنشئ جداول قاعدة البيانات
npx prisma migrate dev --name init

# 4. شغّل المشروع
npm run dev
```

افتح `http://localhost:3000`.

## إعداد قاعدة البيانات خطوة بخطوة

يمكنك استخدام أي قاعدة PostgreSQL مُدارة:

**خيار Supabase (مجاني للبدء):**
1. أنشئ مشروعًا جديدًا على supabase.com.
2. من Project Settings → Database، انسخ Connection String (وضع "URI").
3. ضعه في `DATABASE_URL` داخل `.env.local`.
4. شغّل `npx prisma migrate dev --name init`.

**خيار Neon / Railway / قاعدة على VPS خاص (مثل OptikLink):**
نفس الخطوات - المهم أن يكون `DATABASE_URL` بصيغة
`postgresql://user:password@host:5432/dbname`، وأن يسمح الجدار الناري بالاتصال
من مكان تشغيل التطبيق.

## النشر

المشروع متوافق مباشرة مع أي استضافة تدعم Next.js (Vercel، أو خادم Node على VPS
عبر `npm run build && npm run start` خلف Nginx). الخطوات العامة:

1. اضبط متغيرات البيئة (`DATABASE_URL`, `NEXT_PUBLIC_SITE_URL`) في منصة النشر نفسها،
   وليس داخل الكود أو أي ملف يُرفع للمستودع.
2. شغّل `npx prisma migrate deploy` مرة واحدة بعد أول نشر لإنشاء الجداول في قاعدة
   بيانات الإنتاج.
3. `npm run build` ثم `npm run start` (أو حسب تعليمات المنصة).

## الأمان والخصوصية - ما تم تنفيذه فعليًا

- التحقق من المدخلات على الخادم عبر `zod` (وليس على الواجهة فقط).
- Prisma يستخدم استعلامات مُعدّة (parameterized) تلقائيًا - لا حقن SQL.
- رمز الرابط العام (`publicToken`) عشوائي بـ12 حرفًا من أبجدية بلا تشابه بصري،
  وليس رقمًا متسلسلاً ولا مشتقًا من اسم أو تاريخ.
- صفحة `/love/[token]` للقراءة فقط - لا يوجد أي مسار API يسمح بالتعديل أو الحذف
  عبر الرمز العام.
- استجابة `GET /api/experiences/[token]` لا تُعيد الـ `id` الداخلي لقاعدة البيانات.
- `robots: { index: false }` على صفحات الاستقبال لمنع فهرستها في محركات البحث.
- لا توجد أي مفاتيح أو أسرار داخل كود الواجهة الأمامية - `DATABASE_URL` يُستخدم
  فقط داخل مسارات الخادم (`src/app/api`, Server Components).
- حدود طول واضحة على كل الحقول (zod + Prisma `@db.VarChar`).

**لم يُنفَّذ بعد (يحتاج قرارًا منك قبل الإنتاج الفعلي):**
- Rate limiting على `POST /api/experiences` (يعتمد على منصة النشر - مثلاً
  Vercel Edge Config أو Upstash Redis).
- سياسة انتهاء صلاحية فعلية تلقائية (الحقل `expiresAt` موجود في قاعدة البيانات
  وجاهز، لكن لا يوجد Cron Job يحذف أو يعطّل التجارب منتهية الصلاحية تلقائيًا).

## ما تم اختباره فعليًا في بيئة التنفيذ، وما لم يُختبر

بيئة التنفيذ التي كتبت فيها هذا المشروع **لا تملك اتصال شبكة** (لا يمكنها تشغيل
`npm install` لتنزيل الحزم) **ولا قاعدة بيانات PostgreSQL فعلية متصلة**. نتيجة لذلك:

✅ **تم فعليًا:**
- كتابة كل ملفات المشروع والتأكد من اتساق المسارات والـ imports يدويًا.
- التحقق **برمجيًا** (سكربت `grep`/`wc` فعلي، ليس تخمينًا) من أعداد عناصر مكتبة
  المحتوى لكل فئة ولغة، ومن عدم وجود أي `id` مكرر عبر 198 عنصرًا - الأرقام في
  الجدول أعلاه نتيجة هذا الفحص مباشرة.

❌ **لم يتم، ويحتاج بيئة بها شبكة وقاعدة بيانات حقيقية:**
- تشغيل `npm install` الفعلي (لم أستطع تنزيل الحزم).
- تشغيل `next build` للتأكد من خلو المشروع من أخطاء TypeScript/JSX وقت البناء.
- تشغيل `prisma migrate` فعليًا وإنشاء الجداول.
- اختبار إنشاء تجربة حقيقية وفتح رابطها من جهاز آخر (السيناريو الذي طلبته).
- أي نشر فعلي على الإنترنت - **لا أدّعي أن الموقع منشور، لأنه فعليًا غير منشور بعد.**

**قبل أول تشغيل عندك، نفّذ بالترتيب:**
```bash
npm install
cp .env.example .env.local   # واملأ DATABASE_URL بقاعدة بيانات حقيقية
npx prisma migrate dev --name init
npm run dev
```
ثم افتح `/create`، أنشئ تجربة، وجرّب فتح الرابط الناتج من متصفح أو جهاز آخر على
نفس الشبكة (أو بعد النشر على رابط عام). لو ظهر أي خطأ TypeScript عند `npm run dev`
أو `npm run build`، ابعتهولي وهصلحه فورًا - الكود لم يُختبر بمترجم TypeScript فعلي
في هذه الجلسة.
